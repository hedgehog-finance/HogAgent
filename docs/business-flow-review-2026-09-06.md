## 经确认后完成的收敛处理

### M1：Long Task 检查点与终态的小范围重构

用户确认：非致命执行组异常可以跳过，审计不可用可以继续，审计重试耗尽后仍尽力交付。这些是提高全自动执行通过率的策略，按特性保留。原审查中“一律停止失败组后续执行”的建议已撤回；没有增加验收门槛或修改审计评分。

实际修复：

- 新执行、进程恢复、澄清后继续共用 `runOrchestrationTurn`，集中保存模式统计、处理错误与发送结束事件，移除重复收尾。
- 规划无法产生合法计划、最终总结调用失败等未被编排内部消化的异常，统一报错；有剩余检查点时复用原归档文件，通过既有 `[Continue Task]` 恢复，普通消息不自动恢复归档。
- `orchestration_completed` 继续用于结束编排区间，不等于任务验收成功。正常返回（包括宽松完成）仍运行交付钩子；未处理异常不触发交付钩子。取消/压缩失败由外层 Prompt Run 收尾，审计模型降级保留原行为。
- 当前和归档检查点在最终总结成功后清理。总结失败保留已处理组游标；恢复重新进入最终审计，并遵循已有重试策略。没有新增“交付阶段”持久化格式，也不承诺跨崩溃恰好交付一次。

验证包括规划报错、统一终态顺序、错误时不交付、显式恢复、取消/压缩/降级，以及审计通过、跳过、重试耗尽三条路径的最终总结失败恢复。原执行组异常跳过和游标兼容测试继续通过。

### M2：WebUI 会话切换期间明确拒绝并发操作

保留原进程重建机制，在被替换的 Session 上设置短暂切换状态。等待旧进程退出期间，重复 `new_session`、RPC 指令、其他 socket 对该会话的 reconnect 均明确报错；不增加消息队列或隐式重放。进程创建后恢复原 stdin 处理，客户端按原协议等待真实 `ready` 再发送。

若浏览器切换中断线，回收旧进程后不再创建新进程。退出等待在退出/超时后清理监听器；重连后的子进程回调绑定固定 Session，异步消息异常统一回报。

本地 WebSocket 回归验证重复切换、命令不写入旧进程、切换后正确路由、跨 socket 重连拒绝和断线不留孤儿进程。

### M3：MCP 操作绑定原连接配置，旧格式明确限制

复用现有 SHA-256 指纹方式，新操作记录 `connectionFingerprint`，仅依据 transport 配置生成。URL、stdio 命令/参数及配置的环境变量引用变化后，禁止旧操作向同名新服务发送 poll/respond/cancel。许可和超时变化不改变连接身份，respond 仍独立重检许可。

旧格式缺少指纹时不推断原服务身份，要求新建操作；无需远端请求的缓存状态/结果读取仍可使用。指纹不包含环境变量的秘密值，不尝试识别相同 URL 背后或相同环境引用的实际服务变更；远端 Task 的跨进程持久性由 MCP 服务负责。

本地 stdio 回归验证配置替换和旧格式均不发送远端请求，纯超时配置变更后仍可继续，权限撤销仍被拒绝。

### M4：子代理执行与格式修复共用预算和取消边界

集中一次 prompt 的预算、取消与模型错误判定。最后允许轮次产出合法最终文本可以 completed；仍需下一轮的工具循环或格式修复返回 max_turns_reached。最多一次格式修复，清空活动工具和 Skill，使用剩余轮次；真实 provider error 不进入格式修复。

父取消/超时沿用既有 timeout 状态，不新增终态枚举；修复期间取消也不能 completed。max_turns 限定正整数，timeout_seconds 限定有限正数，无效输入报错。

回归覆盖最后一轮成功、未完成工具循环、无剩余修复预算、无工具修复、修复中取消和 provider error。
