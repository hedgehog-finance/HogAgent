| 级别 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 分类器和审计只使用自己的静态提示词，遗漏顶层规则快照和当轮受控上下文；进程提示词还可能在同一轮重新读取 | 用共用组合器加载 SYSTEM、根 AGENTS、Hog 追加规则和冻结的进程提示词；分类、审计、无状态调用和子 Agent 继承这些规则，并传递适用的 Runtime Context |
| P1 | 澄清暂停后的 continuation 闭包保留旧执行依赖，可能使用上一轮的工具、凭据与锁定交付策略 | 新外层执行边界更新闭包引用的依赖对象；不同 workspace/session/project/Manifest owner 明确拒绝，原待续任务保留 |
| P2 | 同一个主 Harness 用于规划、分组与收尾，缺少系统层的调用范围；内部 JSON 与主对话交付格式可能冲突 | 增加调用局部的异步 scope；规划、分组与最终回复分别声明范围，子 Agent 显式选择子调用范围；公共规则与专属格式分层，不把 scope 写入共享 workspace 快照 |
| P2 | 分类与分组把复杂任务统一视为必须生成文件，导致纯文本任务也落盘或被要求补文件 | 仅按用户请求或实际适用 Skill 生成业务文件；文字结果可放在 content，output_files 可为空；格式修正和重试提示同步调整 |
| P2 | 最终审计把计划中的全部步骤描述为已执行，且主要看到最后一组回复，影响对部分结果和纯文本成果的判断 | 向最终审计和最终总结传递有界的逐组执行事实与文字结果；重试及重试中澄清恢复按组 ID 保留实际执行过的前序组；兼容中间组失败造成的非连续进度，不凭计划或数组位置推定完成 |
| P2 | 只读规划、无工具回复仍可能声明记忆写入、自扩展或 Skill CLI 写文件能力 | 按实际工具清单生成能力段；无工具/只读调用不注入这些可执行能力说明 |
| P2 | 审计文件检查逐个尝试多个根目录，可能把另一个同名历史文件当作当前成果；绝对路径识别也偏向 Unix | 复用成果解析器已经规范化的声明，按绝对路径或 workspace 相对路径精确定位，不再猜测；非普通文件/读取检查失败标记未验证，明确不存在才标记缺失；提示词中的相对路径基准同步修正 |

`Sub-agent Scheduling & Acceptance Rules` 仍是公共调度、继承与验收的唯一规范；本次补充的是原生执行时的范围选择，没有另建重复的 Sub-agent 业务规范。Gateway 的 `runtime/hogagent.md`、提示词分层文档以及 HogAgent 架构文档同步更新。

## 宽松自动执行原则

首次及重试审计统一使用宽松、以目标为依据的规则，删除重复的严格/宽松提示词分支。单个工具错误、非关键步骤偏差、非必要文件缺失或非阻塞细节，不独立触发整轮失败。实际未完成组作为审计事实，由审计判断是否影响核心目标，不增设“任一组未完成就失败”的硬性门槛。

审计仍使用既有分数阈值和有界重试；只有有证据支持的核心目标未达成、明确硬性要求未满足或阻塞缺陷，才应判定验收不通过。审计不可用、超时或超过调用上限时，保留 skipped/unverified 语义并继续交付已有结果。明确的取消、不可恢复执行错误和外层回合终止事件保持既有处理。宽松策略不授权虚构文件内容、审计通过或步骤完成。
